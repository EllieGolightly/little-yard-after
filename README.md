# 小院之后

一个自己慢慢玩的末日宅家经营小游戏。30,000 元准备金、32 件商品、一栋带院子的房子。采购、储水发电、种植养殖，再给自己做一顿饭。

## 开始玩

Mac 双击 **启动小院.command**，然后保持弹出的终端窗口运行。也可以在本目录执行：

```sh
npm run dev
```

打开 `http://127.0.0.1:4173`。需要 Node.js 20 或以上，没有第三方依赖，不用执行 npm install。网页请通过服务器打开；浏览器直接打开 index.html 不能加载模块。

## 一局怎么玩

1. 从采购手册挑东西，购物袋里可以反复增减。没有准备倒计时。
2. 不知从哪开始，可以装入 **基础清单**（¥24,480），再按喜好调整。点击采购，设施自动安置进院子。
3. 准备满意后关上院门。此后停止购物，剩余的钱保留，不会转换成其他资源。
4. 在菜地选择作物。每天默认自动浇水、喂养；成熟后点击收获，再播种。
5. 看三日天气预报，安排水电、饲料、冰箱和做饭。只有点击 **过完这一天** 才推进时间。
6. 生活 30 天会留下纪念，之后仍可继续经营。基本口粮或饮水不足时有应急补给，使用次数如实记入手记。

关掉页面不会消耗物资。进度自动保存在当前浏览器的 localStorage，附上一份有效存档备份；不同设备、浏览器、网址各有各的存档，**不会自动云同步**。请从顶部的设置按钮导出 / 导入 JSON 存档。购物袋是尚未结算的临时选择，刷新页面后会清空；已经采购的物资和生活进度会保存。

## 第一版的规则

- 天气按固定 12 天循环，提前显示 3 天预报，无隐藏随机惩罚。
- 每日结算顺序：补水与太阳能 → 饮水援助 → 备用发电 / 冰箱 / 灯 → 自动照料 → 吃饭喝水 → 鲜食损耗。
- 默认每天吃 1 份食物，优先消耗蔬菜、蛋、鱼，再吃耐储食品；个人饮水 4 L，炎热天 6 L，有遮阳设施可降回 4 L。
- 雨水需集雨器和净水器配合。太阳能与发电机需蓄电池。购买时会检查配套和储水容量。
- 作物每次播种消耗种子，收获返还种子；温室缩短 1 天，堆肥增加 2 份产量。
- 鸡、鸭、鱼分别按 2 / 3 / 7 个照料日生产。缺水、缺饲料只暂停进度。
- 做饭需要灶台，2 份蔬菜 + 1 份蛋或鱼 + 1 L 燃料，得到 6 份耐储食物和 3 天舒适加成；每天最多一次。
- 有电的冰箱避免当日变质；未保鲜时每逢第 4、8、12…天，各类鲜食损耗 25%（向下取整，至少 1 份）。

具体数值集中在代码与商品说明里，属于轻松经营游戏的平衡设定。

## 继续迭代

这是没有框架依赖的 ES Modules 网页，游戏规则不依赖界面，之后可以逐步加事件、角色、地图或更换前端框架。

| 文件 | 负责什么 |
| --- | --- |
| `src/data.js` | 商品、价格、作物、天气和起步清单 |
| `src/engine.js` | 纯函数规则、采购、每日结算、动作和存档校验 |
| `src/storage.js` | 本地保存、备份恢复、导出与导入 |
| `src/scene.js` | 随设施和作物状态变化的原创 SVG 小院 |
| `src/app.js` | 页面、按钮、购物袋、日结弹窗 |
| `src/styles.css` | 桌面、平板、手机布局 |
| `tests/` | 规则与存档的实质验证 |

新增商品先改 data；新增机制改 engine 并增加针对性检查；新增事件可以在每日结算末尾接入事件数据。改变存档结构时需要版本迁移，再提高 `version`；不要直接抛弃旧存档。

```sh
npm test       # Node 原生测试
npm run build # 将纯静态网页复制到 dist/
```

`dist/` 可部署到静态网站托管；没有后端、账户系统、外部字体或外部图片请求。
